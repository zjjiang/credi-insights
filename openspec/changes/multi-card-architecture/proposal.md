# Proposal: 多卡架构

## 问题

当前系统假设单卡单配置：
- Setting 存全局 IMAP 配置，无法区分多张卡的邮箱订阅
- Transaction/Upload 记录 cardLast4，但无「卡」实体，无法关联账单周期、别名
- 首页直接展示交易列表，缺少卡片选择层级
- 用户有多张信用卡（招商、浦发），需要独立管理每张卡的账单周期和日推订阅

## 目标

重构为多卡架构，每张卡独立管理：
- 卡片实体（Card）：记录卡号、银行、账单日、IMAP 订阅配置
- 卡片选择器首页：展示所有卡片，点击进入该卡的交易详情
- 卡级日推同步：每张卡独立触发邮箱同步
- 数据关联：Transaction/Upload 绑定 cardId

## 用户体验

1. **首页 = 卡片选择器**：大卡片展示每张卡（卡号、银行、本月累计、账单日）、`[+ 新增卡片]` 入口
2. **卡片详情页**：单列交易流水、按日分组、来源 Badge（日推/已入库）、`[🔄 同步邮箱]` 按钮
3. **新增卡片**：表单配置卡号、银行、账单日、还款日、IMAP 订阅（host/port/user/password/subject）

## 非目标

- 浦发银行解析器（后续单独迭代）
- 仿真卡面视觉设计（先用简洁卡片）
- 跨卡合并视图（每张卡独立查看）

## 约束

- 现有数据需迁移：已有 Transaction/Upload 需手动关联到新建的 Card
- IMAP 配置每卡独立（D1 选项 A），不共享全局配置
- 保持日结视图逻辑（覆盖度追踪、按日分组、缺口标记）
