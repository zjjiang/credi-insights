# Proposal: 卡片详情页拆分活跃流水与历史账单

## 问题

`restore-card-report-panel` change 把月报告、重新分类、未分类处理三个功能接回卡片详情页后，页面结构是：本月概览 → 账单周期面板（报告/分类/明细） → 按日流水列表，三段纵向堆叠。用户反馈翻到按日流水时分不清哪些是当前还没出账单的交易、哪些是已经被账单核对过的历史交易，一度误以为最近几天的日推数据丢失（实际数据完好，只是混在一起不好定位）。

调查同时发现一个数据完整性风险：日推交易靠指纹（日期+卡号+金额）跟账单解析结果精确匹配来完成"过账"，指纹不匹配的交易会永久停留在未关联任何账单的状态，即使其发生日期已被完整账单覆盖。任何按日期简单切分"活跃/历史"的方案都可能让这类交易在两个视图里都不可见。

## 目标

把卡片详情页拆分为「活跃流水」「历史账单」两个 tab：
- 活跃流水：默认 tab，展示账期在最新已完成账单之后的交易，外加所有未关联任何账单的交易（不论日期），避免匹配失败的交易永久隐形
- 历史账单：现有的账单周期选择器 + 报告下载/重新分类/未分类处理面板

## 用户体验

1. 打开卡片详情页，默认停在「活跃流水」tab：本月概览 + 「同步日推」按钮 + 按日流水列表（只含未出账单的近期交易和未关联账单的孤儿交易）
2. 切换到「历史账单」tab：「上传月账单」按钮 + 账单周期下拉 + 报告下载/重新分类按钮 + 明细/未分类/大额面板
3. 未关联任何账单的交易始终能在「活跃流水」里找到并处理（如指定分类），不会因为发生日期久远而消失

## 非目标

- 不修复 graduation/指纹匹配算法本身，只解决匹配失败交易的可见性
- 不做孤儿交易的自动归档到某期账单的功能
- 不改历史账单面板按 `uploadId` 查询交易的方式

## 约束

- 「所有 DONE 状态账单里最大的 billingEnd」作为活跃/历史的划线依据；账单账期解析失败（`billingEnd` 为空）时不参与划线计算
- 若卡片没有任何账单能提供有效账期，活跃 tab 不做日期下限过滤，等同于当前全量按日展示的行为
