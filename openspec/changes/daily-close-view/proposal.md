## Why

日抓取(`daily-imap-ingest`)已上线:每日「每日信用管家」邮件经转发拉取入库。但抓来的数据目前没有独立视图,且缺少让「日结」真正可信的机制。

「日结」是日推送存在的意义 —— 用户当天早上就能看到昨天花了多少,而非等月底账单。要让日结可信,必须解决两个缺口:

1. **没有按日视图** —— 日推送数据混在月账单看板里,看不出「昨天/本周」的日粒度消费。
2. **无法信任日结完整性** —— 若某天转发中断、日推邮件没收到,那天数据残缺,但界面无从察觉。当前只存 `imap_last_uid`(保证邮件不丢),不记录「哪些自然日已被日推覆盖」。

## What Changes

- **两级结算模型**:交易有「日结」(时效,次晨完整)和「已对账」(权威,月账单确认)两个可分析状态。日结本身即完整终态,月账单事后盖章。
- **按日 Tab**:独立视图,按自然日分组倒序展示交易。过滤维度为**日期窗口**(非 `source`),交易被月账单对账后仍留在其发生日,不蒸发。
- **覆盖度追踪**:记录已被日推覆盖的自然日,按日单元标「已关账 / 有缺口」,缺口处提示手动补拉。
- **对账毕业高亮**:月账单 Tab 中,从日推带标签毕业过来的交易高亮标注「日推带标」。
- **陈旧未对账人工干预**:日推说了但月账单始终未确认的交易,支持人工删除/清理。
- **cron 每早自动关账**:定时触发 ingest,每天早上自动给昨天关账,形成日结闭环。

## Capabilities

### New Capabilities
- `daily-transactions-view`: 按日 Tab 视图 + 覆盖度提示 + 陈旧交易人工干预 + 毕业高亮

### Modified Capabilities
- `transaction-storage`: 新增日推覆盖度记录;视图过滤维度从 `source` 改为日期/结算状态
- `daily-ingest`: 记录每封日推邮件覆盖的自然日;支持按日期范围手动补拉

## Impact

- **数据库**:新增日推覆盖度记录(Setting 或新表,design.md 决定)
- **UI**:新增「按日」Tab;月账单 Tab 增加毕业高亮
- **API**:按日聚合查询;覆盖度查询;陈旧交易删除;按日期补拉
- **部署**:cron 每早调 `npm run ingest`
- **依赖前提**:`daily-imap-ingest` 已合并(抓取管线就绪)
